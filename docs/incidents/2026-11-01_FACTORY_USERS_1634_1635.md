# Investigation: users 1634 & 1635 (Faker factory accounts)

**Date:** 2026-11-01  
**Mode:** read-only  
**DB:** `d14098_fun`

## Verdict

Both accounts were created by **Cursor QA / agent `tinker` activity**, not by HTTP registration, external bots, or PHPUnit’s sqlite suite.

Root cause: `php artisan tinker` bootstraps **production** `.env` and ran:

`User::factory()->unverified()->create()`

twice while debugging the email-delivery tip on `/email/verify` (agent transcript `81e43986-…`, email-tip QA).

## Registration route

**None.** Created via Eloquent factory in CLI (bypasses Turnstile, budgets, OTP).

## Security controls (verified)

- `TURNSTILE_ENABLED_WEB=true` / `enabled_api=false`
- Registration budgets + OTP budget config active
- Controls **did not apply** because registration HTTP was not used

## PHPUnit isolation

- `phpunit.xml` sets `DB_CONNECTION=sqlite`, `DB_DATABASE=:memory:` (**without** `force="true"` — harden later)
- Feature tests use `RefreshDatabase`; `api-*.log` lines with `example.com` are mostly **test traffic** writing to the shared log with production `APP_URL`, not proof of prod inserts
- These two rows match **tinker**, not a migrate:fresh accident

## Recommended actions (owner; not executed)

1. Treat 1634 and 1635 as disposable QA accounts (deactivate or delete after approval).  
2. Ban CLI `User::factory()->create()` against production; use sqlite/`RefreshDatabase` or an isolated DB.  
3. Add `force="true"` on PHPUnit `DB_*` env entries.  
4. Optional: guard factories when `app()->environment('production')`.
