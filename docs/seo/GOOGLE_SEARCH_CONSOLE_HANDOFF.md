# Google Search Console handoff

**Status:** Not verified. Not submitted. No indexing request has been sent.  
This checklist is for the site owner. Completing it does not require another code deploy, but the canonical redirects should be deployed first so Google is not asked to index `www` or `http`.

Canonical property: **Domain** `funnity.com`  
Canonical page: `https://funnity.com/`  
Sitemap: `https://funnity.com/sitemap.xml`

Do not verify only `https://www.funnity.com`. That host is a duplicate and will 301 to the apex after deploy.

## 1. Verify the domain property

1. Open [Google Search Console](https://search.google.com/search-console) with the Google account that should own the property.
2. Add property → **Domain** → enter `funnity.com` (no scheme, no `www`).
3. Google shows a TXT record, typically named `@` or `funnity.com`, with a value starting with `google-site-verification=`.
4. Add that TXT record at the DNS host for `funnity.com`. Do not invent the token in the repository.
5. Wait for DNS to publish, then click **Verify** in Search Console.
6. Record the date verification succeeded. Until that screen says verified, this item is incomplete.

A URL-prefix property for `https://funnity.com` is optional and does not replace the domain property. If you add it, use the HTML file or meta tag Google issues for that prefix only.

## 2. Submit the sitemap

1. After verification, open the `funnity.com` property.
2. Sitemaps → enter `https://funnity.com/sitemap.xml` → Submit.
3. Success means Google fetched the file. It does not mean the URLs are indexed.
4. Write down: discovered URL count, status (Success / Couldn't fetch), and the date.

If the fetch fails, check that `https://funnity.com/sitemap.xml` returns `200` and `Content-Type: application/xml`. The file is generated by Laravel, not stored as a static file in `public/`.

## 3. Inspect the homepage

1. URL inspection → paste `https://funnity.com/`.
2. Wait for the live test.
3. Record:
   - “URL is on Google” or “URL is not on Google”
   - Page fetch: successful or not
   - Indexing allowed: Yes
   - User-declared canonical: `https://funnity.com`
   - Google-selected canonical, if shown
   - Last crawl time
4. Repeat for one real upcoming event URL, not event 602, 501, or 502.

## 4. Request indexing

1. On the homepage inspection result, use **Request indexing** only if the URL is unknown or the new title should be recrawled.
2. Google may refuse or queue the request. Either outcome is a completed step if you record it.
3. Do not use the Indexing API for these pages. Ordinary website URLs are outside that API’s content types.

## 5. Index coverage

Open **Pages** (indexing) after the first crawl.

Record counts for:

- Indexed
- Discovered — currently not indexed
- Crawled — currently not indexed
- Duplicate, Google chose different canonical
- Excluded by `noindex`
- Soft 404
- Not found (404)
- Blocked by robots.txt
- Manual actions (Security & Manual actions). Record “none” only when the UI says so.

“Discovered — currently not indexed” on old or template events is a quality outcome. It is not fixed by adding more meta tags.

## 6. Branded queries

Performance → Search results.

1. Add a query filter for `funnity` (and a second filter for `funnity.com` if you want exact-host demand).
2. Date range: after verification, then again at 7, 14, and 30 days.
3. Record impressions, clicks, and average position for the query, and the pages that received impressions.
4. Zero impressions means Google has not shown the URL. It is not a ranking drop.

Expect the word “Funnity” to keep showing funnityweb.com until this site is indexed and has its own citations. Do not read another company’s listing as a penalty on funnity.com.

## 7. What not to claim

- Do not say the property is verified until step 1 shows a success date.
- Do not say the sitemap was submitted until step 2 shows a status.
- Do not say the homepage is indexed until URL inspection says the URL is on Google.
